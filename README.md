# 会话共享与一致性组件

多实例部署下的会话共享组件：节点与存储用内存对象模拟，中心存储 + 版本号 CAS
保证任意节点读到完整版本，支持粘性/非粘性两种模式、并发冲突策略、实例扩缩容、
过期清理与运行统计。

## 运行方式

```bash
./mvnw -q verify
```

## 架构

```
SessionNode (服务实例, 粘性/非粘性, 本地缓存)
      │  读写经 SessionCluster 转发 + 缓存一致性广播
SessionCluster (集群: 扩缩容、广播、统计入口)
      │
SessionStore (中心存储: ConcurrentHashMap.compute 原子 CAS)
      │
Session (不可变快照: id / version / attributes / 时间戳 / TTL / owner)
```

- `Session` 不可变，每次更新产生全新实例（版本号 +1）。存储中的替换是原子的，
  因此**任何节点读到的都是某个完整版本**，不可能读到更新到一半的状态。
- 所有写操作在 `ConcurrentMap.compute` 中原子完成，更新采用版本号 CAS：
  调用方带上读取时看到的版本号，版本不一致即判定为并发冲突。

## 粘性与非粘性模式的一致性要求

| 模式 | 路由 | 一致性要求 |
|------|------|-----------|
| STICKY（粘性） | 会话归属创建它的节点（owner），请求路由到 owner | 较弱：owner 是唯一写者，读本地缓存即一致；其他节点经中心存储读取。owner 下线（缩容）时会话回收进中心存储，由其他节点接管 |
| NON_STICKY（非粘性） | 任意节点都可读写 | 较强：每次读写都经中心存储做版本 CAS，保证所有节点读到最新已提交的完整版本（线性一致的写、读己之写） |

## 并发冲突策略（按版本号检测）

同一会话在不同节点被并发更新时，以期望版本号与存储版本号不一致判定冲突，
并按集群级策略处理（`ConflictStrategy`）：

- **REJECT_STALE（拒绝后者，乐观锁）**：版本落后的更新直接抛出
  `VersionConflictException`，调用方需重新读取后重试。适合不能丢更新的场景。
- **LAST_WRITE_WINS（按时间取新）**：冲突时不报错，比较写入时间戳与存储版本的
  最后修改时间——时间戳更新的写覆盖生效，更旧的写被丢弃
  （`UpdateResult.applied() == false`）。适合可容忍覆盖、追求可用的场景。

两种策略下冲突都会计入 `versionConflicts` 统计。

## 扩容与缩容

- **扩容**：`addNode()` 新实例加入时从中心存储 `snapshot()` 同步全部会话，
  加入后即可读取全部会话；计入 `scaleOuts`。
- **缩容**：`removeNode()` 实例离开前把本地会话 `restore()` 回收到中心存储
  （仅版本/时间戳更新的副本才覆盖，避免旧副本冲掉新版本），其上会话不丢失；
  计入 `scaleIns`。

## 过期清理

会话带 TTL（`NEVER_EXPIRES` 表示永不过期）。两条清理路径：

1. 主动：`cleanupExpired()` 扫描清理全部过期会话，返回清理数量；
2. 惰性：读取到已过期会话时立即移除并返回 `Optional.empty()`。

清理后读取返回**明确的不存在结果**（`Optional.empty()`），清理数计入
`expiredRemovals`。

## 统计

`SessionMetrics` 提供：版本冲突次数、扩容次数、缩容次数、过期清理数；
存活会话数由 `SessionCluster.activeSessionCount()` 实时计算。

## 测试

`SessionSharingTest`（10 个用例）覆盖：创建/读取/更新/失效与版本递增、
任意节点可读、并发更新期间只读到完整版本、REJECT_STALE 与 LAST_WRITE_WINS
两种冲突策略、扩容后新实例读全部会话、缩容不丢会话、过期清理与明确不存在结果、
各项统计计数、粘性模式一致性。

## 任务提示词（原始需求）

我们的服务多实例部署，用户会话要在实例间共享，实例扩容时不能丢会话。请从零实现一个会话共享与一致性组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ），节点与存储用内存对象模拟。要求：1) 支持会话创建、读取、更新与失效，会话带版本号；2) 支持多节点共享：任意节点都能读到会话，读到的内容必须是某个完整版本；3) 支持会话粘性与非粘性两种模式，说明各自对一致性的要求；4) 支持并发更新冲突：同一会话在不同节点被并发更新时，按版本号检测冲突并按策略处理（拒绝后者或按时间取新），策略写进 README；5) 支持实例扩容与缩容：扩容后新实例能读取全部会话，缩容时其上的会话不得丢失；6) 支持会话过期清理，清理后读取要返回明确的不存在结果；7) 提供统计：会话数、版本冲突次数、扩容缩容次数与过期清理数；8) 测试覆盖创建读取更新、完整版本读取、并发冲突两种策略、扩缩容不丢会话、过期清理与统计；`mvn -q verify` 一条命令跑通。
